CP-EXP-M-001

Campo Detalle
ID del caso CP-EXP-M-001
Nombre Flujo completo de usuario: registro → login → artículo → seguir → feed → comentar → favoritar
Funcionalidad / Endpoint cubierto Múltiples: POST /api/users, POST /api/users/login, POST /api/articles, POST /api/profiles/{username}/follow, GET /api/articles/feed, POST /api/articles/{slug}/comments, POST /api/articles/{slug}/favorite
Precondiciones API corriendo en http://localhost:8000. Base de datos limpia (sin usuarios previos). Swagger UI accesible en http://localhost:8000/docs.
Datos de entrada Usuario A: {"user": {"username": "usuarioA", "email": "usuarioa@test.com", "password": "password123"}}
Usuario B: {"user": {"username": "usuarioB", "email": "usuariob@test.com", "password": "password123"}}
Artículo: {"article": {"title": "Artículo de Prueba", "description": "Descripción", "body": "Contenido del artículo", "tagList": ["test", "qa"]}}
Pasos de ejecución 1. Abrir http://localhost:8000/docs
2. Registrar Usuario A con POST /api/users
3. Registrar Usuario B con POST /api/users
4. Hacer login como Usuario B con POST /api/users/login, copiar el token
5. Clicar "Authorize" en Swagger, ingresar Bearer {token de B}, clicar Authorize
6. Crear un artículo como Usuario B con POST /api/articles
7. Hacer login como Usuario A, copiar token y re-autenticarse en Swagger
8. Seguir a Usuario B con POST /api/profiles/usuarioB/follow
9. Verificar feed con GET /api/articles/feed — el artículo de B debe aparecer
10. Comentar el artículo de B con POST /api/articles/{slug}/comments
11. Marcar el artículo de B como favorito con POST /api/articles/{slug}/favorite
12. Verificar el artículo con GET /api/articles/{slug} — observar favorited y favoritesCount
Resultado esperado Cada endpoint retorna HTTP 200. El feed de A muestra el artículo de B. El comentario aparece en la respuesta. El campo favorited es true y favoritesCount es 1 en el artículo final.
Resultado obtenido El flujo se ejecutó en Swagger UI detectando múltiples anomalías: registro retornó 200 en lugar de 201 (BUG-01); al seguir usuario B la respuesta retornó following: false (BUG-06); feed sin auth no valida token (BUG-07); al marcar favorito se produjo error HTTP 500 (BUG-05).
Estado Falló
Prioridad Alta

Modo Manual (Swagger UI)
Técnica aplicada Exploratoria

Valor 1: ?limit=19 (justo por debajo del máximo)

Valor 3: ?limit=21 (un punto sobre el límite)
Valor 4: ?limit=100 (muy por encima del límite)

Resultado obtenido Al solicitar GET /api/articles?limit=100 en base de datos con 25 artículos, el backend retornó los 25 artículos en la lista en lugar de respetar el tope máximo especificado de 20 (BUG-09).
